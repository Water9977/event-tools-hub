# Build-Feasibility Scores

Scores all 134 candidates from `01-opportunity-candidates.md` for technical build cost and content-depth potential.

## Methodology

**Technical feasibility** (judgment call, no scraping needed for most): every candidate was reasoned through for what it would actually take to build under a zero-cost, static-hosting (Cloudflare Pages) model.
- **pure-client-side** — runs entirely in-browser (vanilla JS, or a client-side/WASM library bundled at build time), no live external calls, no server. Preferred tier.
- **needs-free-api** — needs live external data at runtime. Only 1 of 134 candidates genuinely required this (Word Synonym Finder). A few pure-client-side candidates have an *optional* free-API enhancement noted in their Notes column (e.g. holiday-aware business-day calculation) — those stay classified pure-client-side because the core tool works without it.
- **needs-backend** — needs server-side storage, accounts, or a real-time cross-device relay. 3 of 134 candidates. Flagged, not scored further on build details.

**Content-depth feasibility**: judged against the bar "genuinely 1200+ words of non-padded original content (real methodology, comparison/reference tables, distinct FAQ angles, worked examples) vs. a tool narrow enough that anything past ~400 words is filler." Calibrated against 17 live competitor scrapes (Firecrawl) spanning every major source-site family, then applied by analogy to the rest of the same family/category:

| Site family | Scrape sample | Finding |
|---|---|---|
| calculator.net | Roman numeral, shoe size, day-of-week, dice roller, concrete (family), resistor calculator | Consistently deep — 700–2,500 words of real rules/history/tables/worked examples per page |
| omnicalculator.com | Cooking measurement, screen size (family), camera FOV (family), moon phase | Consistently deep — modern layout, formula derivation, worked examples, real FAQ |
| gigacalculator.com | Anniversary calculator, sand calculator (family) | Consistently deep — TOC, guide sections, tables |
| unitconverters.net | Typography converter, data transfer converter | Consistently shallow — pure factor tables, zero prose, applies to all 6 niche-physics-unit converters in this batch |
| piliapp.com | JSON validator, PDF merge, screen ruler | Consistently shallow — 20–150 words, mechanical "how to use" only |
| rapidtables.com | RGB→hex, color picker, Ohm's law | Shallow-to-thin — formula + 1-2 worked examples, mostly link-farm to sibling calculators |
| wordcounter.net / convertcase.net | Word counter, case converter hub | Shallow *as currently built* (~250 words; per-mode text is 2-3 sentences) despite being full apps — confirms the gap is UX, not content, for these |
| ginifab.com | Background remover | Shallow *as currently built* (~150 words) but sits on a genuinely richer topic (AI segmentation, use cases) than mechanical image tools — judged deep on ceiling |
| americantent.com (event-planning vendor) | Tent size calculator | Deep — 1,200+ words: seating-style breakdown tables, cost tables, FAQ by guest-count band. Strong validation that a neutral competitor can match/exceed vendor lead-gen content depth without the vendor bias, supporting deep calls across the whole event-planning cluster |

Where a candidate wasn't directly scraped, its score was set by analogy to its closest scraped sibling (same source site, same tool family, or same source-file competitor-quality note).

## Summary

**Technical feasibility (134 candidates):**
- **pure-client-side: 130** — buildable entirely on Cloudflare Pages static hosting with vanilla JS or bundled/WASM libraries, zero marginal cost, no API keys, no third-party downtime risk.
- **needs-free-api: 1** — Word Synonym Finder Ranked by Popularity/Commonality (Datamuse API, free/no-key, or a bundled static dataset as a pure-client-side alternative). Three additional pure-client-side candidates (Working Days Calculator, My Coordinates, Fuel Cost Calculator) have an *optional* free-API enhancement noted but work fully without one, so they're counted as pure-client-side.
- **needs-backend: 3** — rejected/flagged, out of scope for the zero-cost model: Webpage/Doc-to-PDF Converter (the webpage-URL-fetch piece needs server-side headless rendering; the doc-upload piece alone is pure-client-side), Event Guest List/RSVP Tracker (real guest-response collection needs server storage), Remote-Controlled Presenter Countdown Timer (needs a cross-device real-time relay).

**Content-depth (134 candidates):**
- **deep: 64** — genuine 1200+-word potential confirmed either directly (17 competitor scrapes) or by strong analogy to a scraped sibling in the same site/tool family. Concentrated in: the calculator.net/omnicalculator/gigacalculator-style calculator families (dates, construction materials, electronics, physics/geo niche calculators), the event-planning cluster (strongest single confirmation: americantent.com's tent-size calculator), select dev-reference tools (hash generator, JSON validator, binary/hex/base64 toolkit), and a handful of generators where real methodology exists (dice roller, coin flip, password generator, QR code generator, random number generator).
- **shallow: 70** — mechanical single-function utilities where the tool's core action *is* the entire value proposition: niche physics/engineering unit converters (6 of them), most image/PDF/file/audio/video transforms, most random-picker/generator novelty tools, basic case/text tools, color-conversion/reference tools, and measurement-display tools (rulers, protractors, device-size comparisons). For these, competitor thinness (confirmed on unitconverters.net, piliapp.com, rapidtables.com) matches the tool's actual content ceiling rather than reflecting a content gap to exploit — differentiation for this half of the list has to come from UX/speed/no-signup, not from out-writing competitors.
